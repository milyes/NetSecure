2. Rapport technique complémentaire

2.1 Contexte

  • Produit : Azure AI Search — Indexer avec Custom WebApiSkill.
  • Architecture : pipeline RAG.
  • Vecteur analysé : requête sortante du Skill vers un endpoint contrôlé par un attaquant.

2.2 Scénario de test

  • Objectif : démontrer l’accès à l’IMDS (169.254.169.254) via l’adresse IPv4-mapped IPv6 ::ffff:169.254.169.254.
  • Prérequis : compromission préalable des identifiants du Skill.
  • Impact : exfiltration possible d’un jeton d’identité managée en cas de RBAC insuffisant.

2.3 Recommandations

  • Bloquer les IP de métadonnées au niveau du VNet / sous-réseau du Skill Host.
  • Avertissement documentation WebApiSkill (SSRF + IMDS).
  • Allowlist des URL d’entrée.
  • Private Endpoint inbound, Shared Private Links outbound, executionEnvironment Private.

2.4 Conclusion d’archivage

La classification « by design » n’exonère pas d’une défense en profondeur : désactiver l’accès public, exposer Search via Private Endpoint, emprunter des Shared Private Links (executionEnvironment: Private), isoler le Skill Host et interdire 169.254.169.254 ainsi que ::ffff:169.254.169.254. Ces mesures complètent l’allowlist d’URL et le moindre privilège de l’identité managée.

7. Configuration DNS : CNAME et enregistrements A

Le CNAME public est publié par Azure. Il ne se crée pas manuellement. L’intégration consiste à résoudre le nom privatelink vers un record A (IP privée du Private Endpoint).

ContexteNomTypeValeur
Internet<svc>.search.windows.netCNAME<svc>.privatelink.search.windows.net
Internet<svc>.privatelink.search.windows.netCNAMEendpoint public Microsoft
VNet + zone liée<svc>.privatelink.search.windows.netA10.x.x.x (PE)
 
az network private-dns zone create --resource-group <rg> --name privatelink.search.windows.net

az network private-dns link vnet create \
  --resource-group <rg> --zone-name privatelink.search.windows.net \
  --name link-search-vnet --virtual-network <vnet> --registration-enabled false

az network private-dns record-set a add-record \
  --resource-group <rg> --zone-name privatelink.search.windows.net \
  --record-set-name <nom-service-search> --ipv4-address <ip-privee-du-pe>

Conditional forwarder on-premises : domaine parent (search.windows.net), pas privatelink.*, vers 168.63.129.16 ou Private Resolver inbound.

nslookup <svc>.search.windows.net
# Dans le VNet : Nom = <svc>.privatelink.search.windows.net ; Address = 10.x.x.x

8. Gérer les zones DNS privées

Principes

  • Une zone par nom officiel, partagée par toutes les instances du même type de service.
  • Hébergement central (hub DNS), puis liens VNet vers les spokes.
  • Noms exacts de la matrice Microsoft.
  • registration-enabled: false sur les liens Private Link.

Inventaire RAG

Zone privéeUsage
privatelink.search.windows.netInbound Search
privatelink.blob.core.windows.netSources, cache, knowledge store
privatelink.dfs.core.windows.netADLS Gen2
privatelink.vaultcore.azure.netKey Vault
privatelink.azurewebsites.netFunction / App Service + record scm
privatelink.openai.azure.comEmbeddings Azure OpenAI

Cycle de vie

  • Création : zone centrale, liens VNet, DNS zone group (max. 5 zones ; une seule zone par nom dans le groupe).
  • Exploitation : laisser le zone group maintenir le record A ; éviter les A manuels en parallèle ; limiter le RBAC à Private DNS Zone Contributor.
  • Suppression : retirer d’abord le PE ou le zone group, puis le record orphelin, puis la zone si elle n’a plus de référence.
az network private-dns zone list --query "[].{name:name,rg:resourceGroup}" -o table

az network private-dns link vnet list \
  --resource-group <rg-dns> \
  --zone-name privatelink.search.windows.net -o table

az network private-dns record-set a list \
  --resource-group <rg-dns> \
  --zone-name privatelink.search.windows.net -o table

az network private-dns link vnet create \
  --resource-group <rg-dns> \
  --zone-name privatelink.search.windows.net \
  --name link-<spoke> \
  --virtual-network <id-ou-nom-du-spoke> \
  --registration-enabled false

Contrôles

  • nslookup depuis le Skill Host : CNAME privatelink + A privée.
  • Portail PE → Configuration DNS : zone group Succeeded.
  • Éviter deux zones identiques liées au même VNet.
  • Policy : interdire la création de zones privatelink.* hors de la subscription réseau centrale.
