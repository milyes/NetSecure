Sécuriser Azure AI Search

Contrôles client pour un service Search utilisé dans un pipeline RAG (Indexer + Custom WebApiSkill). Private Link isole le réseau. Il ne remplace pas l’identité, la liste blanche d’URL ni le journal.

1. Réseau entrant

  1. Palier Basic ou supérieur
  2. Private Endpoint dans un sous-réseau dédié
  3. DNS privatelink.search.windows.net
  4. Désactiver l’accès public après tests

2. Réseau sortant

  1. Shared Private Links vers Storage, Key Vault, Function
  2. Approuver les connexions cibles
  3. Indexeur : executionEnvironment: Private
  4. Skillsets avancés : vérifier le SKU (souvent S2+)

3. Identité

  1. Identité managée du service Search
  2. RBAC Entra ID au moindre privilège
  3. Désactiver les clés API une fois le RBAC validé
  4. Aucune attribution large (Contributor abonnement)

4. Custom WebApiSkill

  1. Liste blanche de domaines
  2. Héberger le skill en privé
  3. NSG : bloquer les IP de métadonnées
  4. Journaliser les appels sortants

Private Link ou Service Endpoint

Critère Service Endpoint Private Link
Adresse IP publique du PaaS IP privée dans votre VNet
Instance Niveau service Ressource nommée
On-premises Non natif VPN / ExpressRoute
Exfiltration Protection moyenne Plus forte
Coût Base gratuite Heure + Go traités

Ordre recommandé

  1. Identité managée + RBAC, puis retrait des clés API
  2. Private Endpoint + DNS privé
  3. Tests depuis le VNet ou le VPN
  4. Couper l’accès public
  5. Shared Private Links et indexeurs privés
  6. Isolation du skill, liste blanche, NSG
  7. CMK Key Vault si exigence de conformité
  8. Journaux Diagnostic Settings et alertes

Classification MSRC « by design » : le durcissement réseau et applicatif reste une responsabilité client. Les démos zerotrust.html, protection.html illustrent la couche entrée / sensibilisation, pas le Private Endpoint Azure.
